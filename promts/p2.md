# Continue Implementation - Wallet Top-up & File Upload

## Task 1 - Implement a Temporary (Mock) Wallet Top-up System

Until a real payment gateway is integrated, implement a temporary/mock payment system that simulates successful payments.

### Requirements

* Users must have a wallet balance.
* Add a **"Top Up Wallet"** page/modal.
* Display several predefined recharge amounts such as:

  * 100,000
  * 250,000
  * 500,000
  * 1,000,000
  * 2,000,000
* Also allow users to enter a **custom amount**.
* Validate that the custom amount is greater than zero and within a reasonable maximum limit.
* After clicking **Recharge**, simulate a successful payment and increase the user's wallet balance.
* Save the transaction in the database.
* Every transaction should include:

  * Transaction ID
  * User ID
  * Amount
  * Status (Success)
  * Created At
  * Payment Method (Mock)
* Display the updated wallet balance immediately after the recharge.
* Add a **Wallet History** section showing previous recharge transactions.

# Task 2 - Fix File Upload

The frontend currently contains the file upload UI, but it is not functional.

Implement complete file upload support from frontend to backend.

## Frontend Requirements

* The upload component must actually send files to the backend.
* Support selecting multiple files.
* Show upload progress.
* Show uploaded file names.
* Allow removing files before submission.
* Validate maximum file size.
* Display meaningful validation errors.

Accept common file types, including but not limited to:

* PDF
* DOC
* DOCX
* XLS
* XLSX
* PPT
* PPTX
* TXT
* CSV
* ZIP
* RAR
* 7Z
* PNG
* JPG
* JPEG
* GIF
* WEBP
* SVG
* MP4
* AVI
* MOV
* MKV
* MP3
* WAV

The frontend should send files using **multipart/form-data**.

---

## Backend Requirements

Implement the complete upload pipeline.

* Accept multipart/form-data requests.
* Validate uploaded files.
* Validate MIME types.
* Validate file size.
* Store uploaded files safely.
* Generate unique filenames to avoid collisions.
* Save file metadata in the database, including:

  * File ID
  * Original filename
  * Stored filename
  * File size
  * MIME type
  * Upload date
  * Uploaded by
* Return uploaded file information to the frontend.
* Implement proper error handling and validation.

* Previously uploaded files can be downloaded.
